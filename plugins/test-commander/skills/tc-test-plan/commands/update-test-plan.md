# /tc:update-test-plan

Keep the test plan current: regenerate the requirement → coverage map from the
latest inventory and traceability, without disturbing the human-owned plan.

## Inputs

- `<workspace>/requirements/requirements-inventory.md` — the parsed REQ-ID list (required).
- `<workspace>/traceability/requirements-map.md` — per-requirement downstream links (optional).

## Outputs

- `<workspace>/test-plan/coverage-map.md` — regenerated byte-deterministically.
- `<workspace>/test-plan/test-plan.md` — **never modified** by this command.

## Preconditions

- The workspace exists (`/tc:init` has run). Otherwise exit 2.
- The requirements inventory exists and has REQ rows. Otherwise exit 2.

## Behavior

1. Resolve the workspace; refuse if uninitialized.
2. Parse the inventory and the traceability map.
3. Recompute each requirement's coverage status.
4. Overwrite `coverage-map.md`. Leave `test-plan.md` untouched (reported as
   `skipped (exists)`).

Run this after `/tc:requirements-to-tests`, `/tc:generate-bdd`,
`/tc:automation-plan`, or any change that moves requirement coverage, so the map
reflects reality. Then update the per-test tables and statuses in `test-plan.md`
by hand (the judgment layer).

## Safety

- Writes only `test-plan/coverage-map.md`. Idempotent and deterministic.

## Implementation

- Helper: `plugins/test-commander/scripts/test_plan.py --refresh` (per D18).
- Run: `python3 <plugin-root>/scripts/test_plan.py <project-root> --refresh`.
